## 1. 项目概览

如窗是一款 macOS 效率工具，目标是让 Dock 操作更接近 Windows 任务栏体验。

| 项 | 说明 |
|----|------|
| 技术栈 | Swift / SwiftUI + AppKit、Accessibility API、CGEventTap |
| 入口 | `LikeWindowsApp` → `AppDelegate` |
| 偏好设置 | `PreferencesWindowController` + `ContentView` |
| 打包 | `scripts/build-dmg.sh` → `build/export/LikeWindows-<版本>.dmg` |
| 系统要求 | 需辅助功能权限；README 写 macOS 18+（以工程 Deployment Target 为准） |

### 1.1 核心模块职责

| 文件 | 职责 |
|------|------|
| `QuickShowHideService` | CGEventTap 拦截 Dock 左键、解析 Dock 图标命中、前台状态、缓存 |
| `DockClickRouter` | 点击路由：仅单窗前台隐藏，或多窗放行系统 |
| `AppWindowInspector` | AX 窗口枚举、激活/最小化/关闭、弹窗列表构建与缓存 |
| `DockInfoPopupService` | 悬停监测、弹窗展示/刷新/关闭 |
| `DockInfoPopupView` / `DockPopupLayout` | 弹窗 UI 与布局计算 |
| `WindowOpenOrderStore` | 窗口打开顺序与指纹稳定身份 |
| `AccessibilityHealth` | 辅助功能是否真正可用（探测 + 缓存） |
| `LaunchAtLoginService` | 登录项（SMAppService） |
| `AppSettings` | UserDefaults 键集中定义 |

## 2. 已实现功能

### 2.1 快速显示/隐藏（Dock 点击）

**开关**：偏好设置 →「快速显示/隐藏」（`AppSettings.quickShowHideEnabled`）

**当前实现行为**（以 `DockClickRouter` 为准）：

| 场景 | 条件 | 行为 |
|------|------|------|
| 单窗口 | App **在前台** 且有可见窗口 | 最小化主窗口（`hideActiveWindowIfVisible`） |
| 单窗口 | App **不在前台** / 无可见窗口 | **不拦截**，交给系统 Dock（打开/恢复） |
| 多窗口 | 任意 | **不拦截** Dock 点击（交给系统）；逐窗操作走悬停弹窗 |
| 任意 | 悬停弹窗正在显示时点击 Dock | 先关闭弹窗，再按上表处理 |

**说明**：

- 「再次点击恢复」依赖**系统 Dock 原生行为**（如窗不拦截后台点击），不是应用内实现的 toggle。
- 有约 `0.15s` 同 PID 点击防抖（`shouldProcessClick`）。
- Event Tap 仅监听左键按下；成功处理时吞掉事件（`return nil`）。

### 2.2 Dock 信息弹窗（悬停）

**开关**：偏好设置 →「Dock 信息弹窗」（`AppSettings.dockInfoPopupEnabled`）

| 能力 | 说明 |
|------|------|
| 悬停探测 | Dock `AXSelectedChildren`（`DockAXHoverProbe`，对齐 DockDoor） |
| 悬停展示 | 多窗口悬停约 0.2s 后弹出**自绘标题列表**（非截图预览） |
| 窗口切换 | 点击列表行 → 激活；当前窗再点则最小化 |
| 窗口控制 | 行内最小化 / 最大化 / 关闭（Windows 风格按钮） |
| 系统窗口排序 | 开：跟随系统 Z 序；关：按打开顺序固定（`WindowOpenOrderStore`） |
| 弹窗保持 | 鼠标在弹窗内时 SelectedChildren 清空不关窗 |
| 自动关闭 | 离开 Dock 且不在弹窗区域；离开时取消延迟展示 |
| 性能策略 | SelectedChildren 事件驱动 + 兜底轮询、短时窗口列表缓存 |

### 2.3 应用生命周期与后台常驻

| 能力 | 说明 |
|------|------|
| 启动显示偏好设置 | 首次启动打开偏好设置窗口 |
| 关闭窗口不退出 | `applicationShouldTerminateAfterLastWindowClosed` → `false` |
| 关闭后隐藏 Dock 图标 | `activationPolicy` 切为 `.accessory` |
| 再次打开偏好设置 | **菜单栏「如窗」图标** →「打开偏好设置」；或 Dock/启动台点击图标 → `applicationShouldHandleReopen`；或二次启动通知已有实例 |
| 单实例（Release） | 已有实例时通知其打开偏好设置，新进程退出 |
| 单实例（Debug） | 保留最新进程并终止旧实例，便于反复 Run |

### 2.4 登录项与权限

| 能力 | 说明 |
|------|------|
| 登录时打开 | `LaunchAtLoginService`（SMAppService）；需批准时引导系统设置 |
| 辅助功能引导 | 未授权时偏好设置展示引导与「打开辅助功能设置」 |
| 运行诊断 | 状态摘要（权限、Event Tap、监测是否工作） |

### 2.5 工程与交付

| 能力 | 说明 |
|------|------|
| App Icon | Icon Composer / Asset Catalog |
| DMG 打包脚本 | `scripts/build-dmg.sh` |
| 菜单栏入口 | `StatusItemController`：后台常驻时通过状态栏打开偏好设置 / 退出 |
| README | 功能说明、截图、构建与打包步骤 |
| 代码注释 | 各核心类型与关键方法已补充基础中文注释（工作区未提交） |

### 2.6 菜单栏图标

工程已接入 `Assets.xcassets/MenuBarIcon.imageset`（template 渲染）。`docs/images/` 下另有黑白素材备份：

- `menubar-black.png` / `menubar-black@2x.png`
- `menubar-white.png` / `menubar-white@2x.png`

## 3. 已处理的问题（历史与现状）

以下按「已合入当前基线或明确回退结论」整理。

### 3.1 稳定性 / 生命周期

| 问题 | 处理结果 |
|------|----------|
| Dock 弹窗崩溃、启动不稳定 | 已在 `e99d998` 等提交中修复，发布 v1.1 |
| 关闭偏好设置后进程退出 / Dock 图标常显 | `e2a262a`：关闭后 `.accessory` 后台常驻；再点图标打开偏好设置 |
| Release 多开实例 | 二次启动通知已有实例并退出新进程 |
| Debug 多实例干扰 | 保留最新进程、终止旧实例 |
| macOS 激活 API 弃用警告 | 已修复（`activate` 相关） |

### 3.2 悬停弹窗与性能

| 问题 | 处理结果 |
|------|----------|
| 悬停性能与弹窗体验 | 节流、缓存、监测相位等（见 `DockInfoPopupService` / `QuickShowHideService`） |
| 窗口列表随焦点乱序 | `WindowOpenOrderStore` 固定打开顺序；可选系统排序 |
| 弹窗布局与窗口列表不同步 | 布局计算与状态签名刷新已处理过（历史修复） |

### 3.3 产品决策：已尝试后回退的功能

以下能力在开发过程中实现过，因稳定性/复杂度问题**已整体回退**，**不在当前代码中**：

| 尝试过的能力 | 回退原因（摘要） | 当前状态 |
|--------------|------------------|----------|
| Option + 点击 Dock 放行系统行为 | 曾作为小步改造加入，随后与大改一并回退 | **未实现** |
| 单窗口真正 toggle（含被遮挡置前） | 前台/焦点判断误判，出现「第一次点击无效」等 | **未实现**（仍为「前台才隐藏」） |
| 多窗口点击弹出选择列表并逐窗切换 | 窗口身份配对、去重、路径不一致导致大量失效 | **未实现** |
| 菜单栏 StatusItem + 黑白模板图标 | 已实现 `StatusItemController` + `MenuBarIcon` | **已接线** |

**结论**：当前产品行为以 README 表格为准——单窗口前台隐藏、多窗口悬停列表；不要按「完整 Windows 任务栏 toggle」预期验收。

## 4. 未处理 / 已知问题与风险

### 4.1 功能缺口（相对曾确认需求或文案）

| 优先级 | 问题 | 说明 |
|--------|------|------|
| 高 | 文案与实现不完全一致 | UI/README 写「切换显示/隐藏」，实现是「仅前台隐藏，恢复靠系统」；被遮挡时第一次点击通常只激活，不隐藏 |
| 高 | 无 Option/Cmd/Shift 修饰键放行 | 带修饰键的 Dock 系统手势可能被 Event Tap 误拦 |
| 中 | ~~多窗口前台点击全部最小化~~ | **已移除**：多窗口 Dock 点击放行系统 |
| 中 | ~~无菜单栏图标入口~~ | **已实现**：菜单栏 Status Item（`StatusItemController`） |
| 中 | 无法加入「系统设置」左侧栏 | macOS Ventura+ 侧栏仅系统扩展；第三方无公开 API（见菜单栏替代方案） |
| 低 | README 打包示例版本号 | 已与工程同步为 `1.2(1)` |

### 4.2 技术债与可靠性风险（审查结论，当前仍存在）

| 优先级 | 问题 | 说明 |
|--------|------|------|
| 高 | 多窗口判定与列表口径可能不一致 | `hasMultipleTrackableWindows` 用 AX 计数；弹窗列表按 fingerprint/`orderKey` 去重，同标题同尺寸窗口可能被合并 |
| 高 | `hideActiveWindowIfVisible` 返回值偏乐观 | `animatedMinimize` 后直接 `return true`，失败时仍可能吞掉点击 |
| 中 | 防抖在操作前 `recordClick` | 隐藏失败后短时间再点可能被防抖挡掉 |
| 中 | Event Tap 非主线程直接 `return false` | 正常挂主 RunLoop 时少见，但无转发兜底 |
| 中 | 单次点击可能多次 AX 全量枚举 | 性能与时序抖动风险（Chrome 等多窗口 App 更明显） |
| 低 | 窗口标题无长度截断 | 极端长标题可能影响布局 |
| 低 | `hostingView` 等可能存在只写不读字段 | 冗余，不影响主路径 |

### 4.3 环境与验收注意

| 项 | 说明 |
|----|------|
| 依赖辅助功能 | 权限被关或 AX「假授权」时功能静默失效；`AccessibilityHealth` 会探测 |
| 应用差异大 | Chrome / Finder / Electron 等 AX 行为不一致，需真机抽测 |
| 无自动化测试 | 窗口操作路径几乎全靠手工回归 |
| Dock 自动隐藏 | 有热区相关逻辑，极端布局（左右 Dock 等）需实测 |

## 5. 建议回归清单

接手后建议至少覆盖：

1. **权限**：未授权 → 引导；授权后快显与悬停均生效  
2. **单窗口**：前台点击隐藏；再点 Dock 由系统恢复  
3. **单窗口后台**：点击应激活/恢复，不应「点了没反应」  
4. **多窗口悬停**：Chrome / Finder 列表完整、行点击激活、控制按钮可用  
5. **多窗口前台点击 Dock**：不拦截，交给系统（不再全部最小化）  
6. **常驻**：关偏好设置 → Dock 图标隐藏且进程仍在；点菜单栏「如窗」图标可打开偏好设置 / 退出  
7. **登录项**：开关与需批准引导  
8. **打包**：`./scripts/build-dmg.sh` 产出可用 DMG

## 6. 后续可选方向（未排期）

按历史小步计划，若要继续增强，建议严格串行、每步验收后再做下一步：

1. **仅** Option（或修饰键）点击放行 —— 改动面最小  
2. 单窗口可靠 toggle（前台隐藏 / 非前台放行系统或置前）—— 先修返回值与防抖  
3. 多窗口点击选择列表 —— 需先统一窗口身份（CG 窗口号）与列表口径
